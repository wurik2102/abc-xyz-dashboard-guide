Полное руководство по исполнительной панели управления

🎯 Назначение Executive Dashboard

Исполнительная панель - это главный инструмент руководителя для ежедневного мониторинга ключевых показателей бизнеса. Дашборд предоставляет полную картину состояния компании в реальном времени и помогает принимать стратегические решения на основе актуальных данных.

📊 Что показывает дашборд на примере (июль 2025)

  • 💰 Продажи: 43,7 МЛН руб (снижение на 16% к прошлому году)
  • 💸 Расходы: 46,8 МЛН руб (снижение на 51% к прошлому году)
  • 💎 Прибыль: 28,7 МЛН руб (снижение на 18% к прошлому году)
  • ⚡ Статус: "🔴 УБЫТКИ" - расходы превышают выручку на 3.1М

Ключевой инсайт: Несмотря на падение продаж на 16%, расходы сократились на 51%, но компания все равно работает в убыток. Карточка "Бизнес-пульс" автоматически определила главную проблему: "Расходы > Выручки".

🏛️ Архитектура исполнительного дашборда

🎯 Концепция "5-секундного инсайта"

Дашборд спроектирован так, чтобы руководитель мог за 5 секунд оценить:

  • Состояние бизнеса: 🟢 Отлично, 🔵 Хорошо, 🟡 Внимание или 🔴 Убытки
  • Тренды: Растем, стагнируем или падаем

  • Возможности: Где потенциал для роста

📅 Система управления временными периодами

🎯 Ключевая особенность дашборда

Все показатели Executive Dashboard динамически адаптируются под выбранный временной период. Это не просто фильтр - это интеллектуальная система, которая пересчитывает все метрики, сравнения и прогнозы в зависимости от вашего выбора.

📅 Селекторы дат в правом верхнем углу

🎮 Элементы управления периодом

Расположение: Правый верхний угол дашборда

Компоненты:

  • Дата начала: 01.07.2025 (левый селектор)
  • Дата окончания: 31.07.2025 (правый селектор)
  • Календарные виджеты: Интерактивные календари для выбора
Выбранный период = от MIN('Календарь'[Date]) до MAX('Календарь'[Date]) На примере: от 01.07.2025 до 31.07.2025 = 31 день

🧠 Автоматическая адаптация визуализаций

Система автоматически определяет оптимальную детализацию:

📅 Дневная детализация (≤31 день)
Show_Daily_NUM = IF([SelectedRangeDays] <= 31, 1, 0)

Активируется когда: Выбрано от 1 до 31 дня

Показывает:

  • Каждый день как отдельную точку
  • Ежедневные планы vs фактические данные
  • Детальную динамику по дням недели

Пример: 01.07-31.07 (31 день) = дневные графики

📊 Недельная детализация (32-90 дней)
Show_Weekly_NUM = IF([SelectedRangeDays] > 31 && [SelectedRangeDays] <= 90, 1, 0)

Активируется когда: Выбрано от 32 до 90 дней

Показывает:

  • Группировку данных по неделям
  • Недельные тренды и сезонность
  • Сравнение недель между собой

Пример: Июнь-август (92 дня) = недельные группировки

📈 Месячная детализация (>90 дней)
Show_Monthly_NUM = IF([SelectedRangeDays] > 90, 1, 0)

Активируется когда: Выбрано более 90 дней

Показывает:

  • Месячные агрегаты данных
  • Долгосрочные тренды
  • Сезонные паттерны по месяцам

Пример: Январь-декабрь (365 дней) = месячные данные

⚙️ Техническая реализация динамических периодов

Система умной визуализации основана на мерах:

Smart_Sales = SWITCH(TRUE(), [Show_Daily_NUM] = 1, [Продажи_руб], // Дневные данные [Show_Weekly_NUM] = 1, [Продажи_руб], // Недельные агрегаты [Show_Monthly_NUM] = 1, [Продажи_руб], // Месячные суммы BLANK() )
Smart_Plan = SWITCH(TRUE(), [Show_Daily_NUM] = 1, [План_продаж_Aggregated], [Show_Weekly_NUM] = 1, [План_продаж_Aggregated], [Show_Monthly_NUM] = 1, [План_продаж_Aggregated], BLANK() )

Прозрачность элементов управляется мерами:

  • Transparency_Daily = 100% если дневной режим, 0% иначе
  • Transparency_Weekly = 100% если недельный режим, 0% иначе
  • Transparency_Monthly = 100% если месячный режим, 0% иначе

💰 Карточка "ПРОДАЖИ" - детальный разбор

📊 Как строится показатель "Продажи"

Основное значение: 43,7 МЛН РУБ

Продажи_руб = SUM('продажи'[Стоимость]) за выбранный период

🧠 Простыми словами:

Что делает система:

  1. Берет таблицу 'продажи' - это все чеки и продажи из наших магазинов
  2. Находит колонку 'Стоимость' - в ней указана сумма каждой продажи
  3. Суммирует все стоимости - складывает все продажи за выбранный период
  4. Получает итог - общую выручку в рублях (43,7 млн)

Пример: Если за день продали на 100 000 руб, на 150 000 руб и на 200 000 руб, то SUM даст нам 450 000 руб за день.

Источник данных: Таблица 'продажи' - все транзакции из кассовых систем

Поля таблицы 'продажи':

  • Период - дата транзакции
  • Магазин - ID торговой точки
  • id_nom - код товара
  • Количество - проданное количество
  • Стоимость - сумма продажи (основа расчета)
  • ЦенаПродажи - цена за единицу

Валюта: Все суммы в рублях, приведены к единому курсу на дату операции

📈 Как рассчитывается динамика: "-16% к прошлому году"

Формула расчета изменений:

Динамика_Продаж_% = DIVIDE([Продажи_руб] - [Продажи_PY], [Продажи_PY]) где [Продажи_PY] = CALCULATE([Продажи_руб], SAMEPERIODLASTYEAR('Календарь'[Date]))

🤔 Как система сравнивает с прошлым годом:

  1. Определяет аналогичный период прошлого года:
    Если сейчас июль 2025, то берет июль 2024 (SAMEPERIODLASTYEAR)
  2. Считает продажи за тот период:
    CALCULATE пересчитывает продажи, но уже для прошлого года
  3. Находит разницу:
    43,7М (сейчас) - 52,1М (было) = -8,4М (падение)
  4. Переводит в проценты:
    -8,4М ÷ 52,1М = -16% (DIVIDE делает деление безопасно)

Результат: "-16%" означает, что продажи упали на 16% по сравнению с тем же периодом прошлого года.

Как работает сравнение:

  • Текущий период: 01.07.2025 - 31.07.2025 = 43,7 МЛН
  • Аналогичный период прошлого года: 01.07.2024 - 31.07.2024 = ~52,1 МЛН
  • Расчет: (43,7 - 52,1) / 52,1 = -16,1%

Интерпретация цветов:

  • 🟢 Зеленый: Рост продаж (положительная динамика)
  • 🔴 Красный: Падение продаж (отрицательная динамика)
  • ⬇ Стрелка вниз: Негативный тренд, требует внимания

💡 Алгоритм действий при падении продаж на 16%

  1. Детализация по магазинам: Проверить, все ли точки показывают падение или проблема локальна
  2. Анализ по товарным группам: Выявить категории с наибольшим падением
  3. Сравнение с рынком: Оценить общие тенденции в отрасли
  4. Проверка операционных показателей: Количество чеков, средний чек, конверсия
  5. Анализ конкурентов: Изменения в конкурентной среде
  6. Сезонные факторы: Сравнить с другими июлями предыдущих лет

🎯 Целевые действия:

  • Усилить маркетинговые активности
  • Пересмотреть ассортиментную политику
  • Провести акции для стимулирования спроса
  • Обучить команду продаж техникам увеличения среднего чека

💸 Карточка "РАСХОДЫ" - система контроля затрат

📊 Как строится показатель "Расходы"

Основное значение: 46,8 МЛН РУБ

Расходы_руб = SUM('Расходы'[Оплачено]) за выбранный период

🧠 Простыми словами:

Что считает система:

  1. Открывает таблицу 'Расходы' - все наши траты и платежи
  2. Смотрит колонку 'Оплачено' - сколько реально заплатили
  3. Суммирует за период - складывает все оплаченные суммы
  4. Получает итог - общие расходы (46,8 млн)

Почему именно "Оплачено"? Потому что важны реальные денежные потоки, а не планы или начисления. Если мы что-то заказали, но еще не оплатили - это не влияет на кассу.

Источник данных: Таблица 'Расходы' - все фактически оплаченные расходы

Структура таблицы 'Расходы':

  • Период - дата оплаты расхода
  • Подразделение - где возник расход
  • Фонд - бюджетная категория (например, "ФОНД МАРКЕТИНГА")
  • Статья - детализация расхода (аренда, зарплата, реклама)
  • Предмет - конкретный объект расхода
  • Оплачено - фактическая сумма к оплате (основа расчета)
  • shop_id - привязка к магазину

⚠️ Важно: Показатель отражает именно оплаченные расходы, а не начисленные. Это дает реальную картину денежных потоков.

📈 Анализ динамики: "-51% к прошлому году" - положительный сигнал!

Как рассчитывается:

Динамика_Расходов_% = DIVIDE([Расходы_руб] - [Расходы_PY], [Расходы_PY]) где [Расходы_PY] = CALCULATE([Расходы_руб], SAMEPERIODLASTYEAR('Календарь'[Date]))

💡 Как понять "-51%" в расходах:

  1. Берет расходы за прошлый год:
    CALCULATE пересчитывает расходы для аналогичного периода прошлого года (~95,5 млн)
  2. Сравнивает с текущими расходами:
    46,8М (сейчас) - 95,5М (было) = -48,7М (экономия!)
  3. Переводит в проценты:
    -48,7М ÷ 95,5М = -51% (DIVIDE безопасно делит)

Важно: Минус в расходах - это хорошо! Означает экономию и эффективность.

Детальный расчет:

  • Июль 2025: 46,8 МЛН руб
  • Июль 2024: ~95,5 МЛН руб
  • Экономия: 48,7 МЛН руб (-51%)

🎯 Почему это хорошо:

  • Продажи упали на 16%, расходы - на 51%
  • Это означает эффективную оптимизацию затрат
  • Компания быстро адаптировалась к снижению выручки
  • Показывает гибкость операционной модели

🔍 Что нужно проконтролировать при таком значительном сокращении расходов:

  • Проверить по фондам: Какие категории расходов сокращены больше всего
  • Качество услуг: Не пострадало ли качество от экономии
  • Инвестиции в развитие: Не сокращены ли критичные для будущего роста расходы
  • Команда: Как экономия повлияла на мотивацию сотрудников

📊 Как строится показатель "Маржинальная прибыль"

Основное значение: 28,7 МЛН РУБ

Валовая прибыль = SUM('продажи'[Стоимость]) - SUM('продажи'[Себестоимость]) или проще: Валовая = Продажи_руб - Себестоимость_проданных_товаров

🧠 Простыми словами - что такое валовая прибыль:

Представьте магазин игрушек:

  1. Купили игрушку за 100 рублей (себестоимость)
  2. Продали за 150 рублей (выручка)
  3. Валовая прибыль = 150 - 100 = 50 рублей

Что делает система:

  • SUM('продажи'[Стоимость]) - суммирует все наши продажи (43,7М)
  • SUM('продажи'[Себестоимость]) - суммирует, сколько мы потратили на товары (15М)
  • Вычитает второе из первого: 43,7М - 15М = 28,7М валовой прибыли

⚠️ Важно: Это еще не чистая прибыль! Из 28,7М нужно вычесть зарплаты, аренду, рекламу и другие расходы.

Что показывает: Сколько денег остается после покрытия прямых затрат на товар

Источник данных - поля таблицы 'продажи':

  • Стоимость - выручка от продажи товара
  • Себестоимость - затраты на закупку/производство товара
  • СуммаСебестоимость - общая себестоимость проданного количества

💡 Важно понимать: Это не чистая прибыль! Из валовой прибыли еще нужно вычесть операционные расходы (зарплаты, аренда, реклама и т.д.)

� Расчет маржинальности: 65,8%

Маржинальность = (Валовая_прибыль ÷ Продажи_руб) × 100% = (28,7 МЛН ÷ 43,7 МЛН) × 100% = 65,7%

Что это означает:

  • С каждого рубля продаж 66 копеек остается валовой прибыли
  • 34 копейки уходит на себестоимость товара
  • Это очень высокая маржинальность для розничной торговли

🎯 Оценка маржинальности:

  • 65,7% - отличный показатель
  • Показывает эффективную ценовую политику
  • Дает хороший запас для покрытия операционных расходов
  • Создает возможности для инвестиций в развитие

📈 Анализ динамики: "-18% к прошлому году"

Как рассчитывается:

Динамика_Прибыли_% = DIVIDE([Валовая] - [Валовая_PY], [Валовая_PY])

Детальный анализ:

  • Июль 2025: 28,7 МЛН руб (маржинальность 65,7%)
  • Июль 2024: ~35,0 МЛН руб
  • Падение: 6,3 МЛН руб (-18%)

🔍 Почему падение прибыли меньше падения продаж:

  • Продажи ↓16%, прибыль ↓18% - почти пропорционально
  • Маржинальность осталась стабильной (~66%)
  • Ценовая политика работает корректно
  • Структура продаж не изменилась критично

🧠 Простыми словами: что делает формула

  1. Считаем продажи в миллионах: Берем все продажи за период и делим на 1 000 000, чтобы получить цифру в миллионах (например, 43,7М вместо 43 700 000)
  2. Считаем расходы в миллионах: То же самое делаем с расходами - суммируем все оплаченные расходы и переводим в миллионы (46,8М)
  3. Вычисляем разницу (баланс): Отнимаем от продаж расходы. Если получается положительное число - прибыль, отрицательное - убыток (43,7М - 46,8М = -3,1М убыток)
  4. Проверяем выполнение плана: Используем готовую меру, которая показывает сколько % от плана мы выполнили (74% в нашем случае)

🚦 Интеллектуальная система статусов

Status = IF(Balance > 0 && PlanExecution >= 1, "🟢 ОТЛИЧНО", IF(Balance > 0 && PlanExecution >= 0.8, "🔵 ХОРОШО", IF(Balance < 0, "🔴 УБЫТКИ", "🟡 ВНИМАНИЕ")))

🤔 Логика принятия решения простыми словами:

Система думает пошагово:

  1. Первый вопрос: "Есть ли прибыль И выполняется ли план на 100%?"
    ➤ Если ДА обоим условиям → 🟢 ОТЛИЧНО
  2. Второй вопрос: "Есть ли прибыль И выполняется ли план хотя бы на 80%?"
    ➤ Если ДА → 🔵 ХОРОШО
  3. Третий вопрос: "Есть ли убытки?" (расходы больше доходов)
    ➤ Если ДА → 🔴 УБЫТКИ (это критично!)
  4. Все остальные случаи: → 🟡 ВНИМАНИЕ (что-то не так, но не критично)

В нашем случае: Balance = -3,1М (убыток), поэтому сразу → 🔴 УБЫТКИ

🟢 ОТЛИЧНО

Условия: Balance > 0 И PlanExecution ≥ 100%

Означает: Прибыльность + план перевыполняется

Действия: Поддерживать текущую стратегию

🔵 ХОРОШО

Условия: Balance > 0 И PlanExecution ≥ 80%

Означает: Прибыльность есть, план близко к выполнению

Действия: Небольшая корректировка для достижения плана

🔴 УБЫТКИ

Условия: Balance < 0 (независимо от плана)

Означает: Расходы превышают доходы

Действия: Экстренные меры по сокращению расходов

� ВНИМАНИЕ

Условия: Все остальные случаи

Означает: Проблемы с выполнением плана

Действия: Анализ и корректировка стратегии

🔍 Автоматическая диагностика проблем

KeyIssue = IF(ExpensesAmount > SalesAmount, "Расходы > Выручки", IF(PlanExecution < 0.8, "План не выполняется", "Всё под контролем"))

🕵️ Как система находит главную проблему:

Алгоритм поиска проблем работает по приоритетам:

    ➤ Если расходы > доходов → "Расходы > Выручки" (это опасно!)
  2. Если с деньгами в порядке, проверяет планы: "Выполняем ли мы план хотя бы на 80%?"
    ➤ Если план < 80% → "План не выполняется"
  3. Если и то, и другое в порядке: → "Всё под контролем"

В нашей ситуации: 46,8М (расходы) > 43,7М (продажи), поэтому главная проблема: "Расходы > Выручки"
